Scanrepo

A small press for a git commit.

How the press works

One edition is one commit. You write the files, seal them into a booklet (a cover plus one page per chunk of source, each with a QR code holding the same bytes), print it, and later scan it back. Scanrepo rehashes every file the git way and rebuilds the tree and the commit. If the ids match the cover, the paper is the commit.

  1. Compose

    Set the repo name, edition (1 for the first printing), branch, and parent (the previous edition's commit, or none). Write the message, author and time: these go on the cover so the commit id can be recomputed. Add files by typing or uploading text files. Each path is a normal file (100644), executable (100755) or symlink (120000, the text is the target). Folders are just / in the path. Files print in git's byte order of paths. A long file splits into page-sized chunks (at most 1800 bytes and 72 lines a page, split at line ends).

  2. Seal and print

    Seal hashes blobs, tree and commit and lays out the booklet. The cover carries repo, edition, branch, commit, tree, parent, author and message, plus the cover code (C|scanrepo1|…). Every page carries its source and a page code (P|scanrepo1|…). Print sends it to paper (print at 100%). Master downloads the .scanrepo file, the digital twin. Keep puts the edition on the shelf in this browser. Test the codes decodes every printed QR on screen and restores from them.

  3. Photograph

    Photograph every page, cover included. Don't crop the codes; shoot them flat and sharp. In Restore use the camera/photos button (codes are decoded on your device), or paste payloads by hand: one per code, separated by a line with just ---. A whole master pasted or uploaded works too. Order doesn't matter and duplicates are fine.

  4. The report

    Sealed: every blob, the tree and the commit recomputed and match the cover. Held: blobs and tree match, but the printing has no author, time or message, so the exact commit id cannot be recomputed. The sample paper-git edition 1 stays Held for that reason. Anything sealed in this app round-trips as Sealed. Rejected: something does not match (a typo, a missing chunk, a code from a different edition); the report says what. Unread: the cover or some pages were not scanned yet; the report lists which.

  5. The next edition

    New edition bumps the edition and sets the parent to this commit. A new printing never overwrites the old one: the shelf is the history. To move to another device, download the Master and restore it there, or scan the booklet.

What doesn't belong on the page

Deltas and packfiles (each page holds full text), binaries (anything with a NUL byte or invalid UTF-8), overlong lines (they split mid-line and are hard to read), and huge files (they chunk into many pages). A 50 KB text repo is a thin booklet; a photo-heavy repo is the wrong thing to print.

Format: scanrepo v1 / 1.1, the same as fitzyracing1/scanrepo-action. Masters from either side restore on the other.
